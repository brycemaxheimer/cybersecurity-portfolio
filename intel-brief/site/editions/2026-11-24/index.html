Huntress details ClickFix lures, fake verification pages and varied payloads

1 source · first reported 23 November 2026

What happened

In a Tradecraft Tuesday recap published 23 November 2026, Huntress reviewed ClickFix social engineering campaigns: convincing lures, the infrastructure behind fake verification pages, a range of delivered payloads, and ways to stop users from pasting malicious commands. The available summary does not name specific payload families, infrastructure indicators or threat actors. ClickFix generally tricks a user into copying a command from a web page and running it themselves, often through the Windows Run dialog or a terminal.

Why it matters

ClickFix bypasses many email and download controls because the user runs the command, so the first reliable signal is usually on the endpoint: explorer.exe launching PowerShell, mshta or cmd with download or encoded content, and Run dialog history in the registry. The source describes the activity as current and the technique is widespread, so Windows fleets with standard users are exposed regardless of patch level.

What to do

  1. Hunt for explorer.exe spawning powershell.exe, pwsh.exe or mshta.exe with web download, Invoke-Expression or encoded-command arguments, and isolate hosts that show it.
  2. Review RunMRU registry values for pasted commands that contain PowerShell, mshta, curl or URLs.
  3. Where the business allows, restrict the Run dialog and mshta.exe for standard users via Group Policy or application control, and enable PowerShell Constrained Language Mode and script block logging.
  4. Enable Defender attack surface reduction rules that block obfuscated scripts and script-launched downloaded content.
  5. Brief users that legitimate CAPTCHA or verification pages never ask them to paste and run commands.

Microsoft says Azure API Management Classic tier flaw was exploited to steal stored API credentials

Microsoft Azure API Management · 2 sources · first reported 23 November 2026

What happened

According to BleepingComputer, Microsoft is warning customers that a vulnerability in the Classic tiers of Azure API Management (APIM) was exploited to steal API credentials stored in the service. Norwegian authorities have linked the flaw to cyberattacks against energy companies. SecurityWeek reports that Microsoft has closed the flaw and that sectors beyond energy were also affected. Neither source gives a CVE, a disclosure timeline or technical details of the exploitation.

Why it matters

Microsoft confirms in-the-wild exploitation, so any credentials stored in a Classic-tier APIM instance should be treated as possibly exposed even though the service-side flaw is now fixed. Stolen subscription keys, named values or backend secrets give an attacker access to the APIs and backend systems behind them. Customers cannot patch this themselves; credential rotation and review of how those credentials have been used are the only remaining controls.

What to do

  1. List every Azure API Management instance on a Classic tier across all subscriptions and check Azure Service Health and the Microsoft notifications for any tenant-specific alert.
  2. Rotate all credentials stored in affected instances, including subscription keys, named values, backend credentials, certificates and any secrets for downstream services.
  3. Review backend and API access logs for affected APIs for calls from unfamiliar IP addresses, odd user agents or unusual volumes since the earliest exposure window Microsoft gives.
  4. Review Azure Activity Log entries for API Management operations that read or list secrets, keys or named values, and confirm each one maps to a known administrator or pipeline.
  5. Where possible, move APIM secrets into Azure Key Vault references with managed identity, and consider migrating off Classic tiers.

NVD says it can be triggered by a runtime command sent through sendcmd or an unauthenticated zmq filter, and may lead to a crash or code execution. The other four are a heap overflow in the WAV muxer from zero-channel audio (CVE-2026-135722), a double free in the IMF Composition Playlist parser (CVE-2026-135723), an out-of-bounds read in the scale filter reachable through sendcmd, zmq or azmq commands (CVE-2026-135739), and a heap out-of-bounds write in the readeia608 filter from crafted high bit depth video (CVE-2026-135740).

Why it matters

FFmpeg is embedded in many media-processing servers, transcoding pipelines, upload handlers and desktop applications. Any service that processes untrusted media, or exposes a zmq or azmq filter control socket, can be made to crash and possibly run attacker code. No exploitation is known, none of the CVEs are in CISA KEV, and EPSS scores are low (0.2% to 0.7%). However, public proof-of-concept code reportedly exists for four of the five CVEs, so patching should not wait for the normal cycle on internet-facing media pipelines.

What to do

  1. Upgrade FFmpeg and its libraries (libavfilter, libavformat) to 9.1 or a distribution build carrying the fixes, starting with services that process untrusted uploads or streams.
  2. Find FFmpeg pipelines that use zmq or azmq filters and either remove those filters or restrict their control sockets to localhost or trusted hosts, since NVD notes they accept commands without authentication.
  3. Inventory applications that bundle their own FFmpeg or libav* libraries, because OS package updates will not patch them, and track the vendors' updates.
  4. Run media transcoding in sandboxed, low-privilege containers and alert on repeated FFmpeg crashes, which may indicate attempts to trigger these bugs.

ClickFix: when the user runs the attacker's command for them

ClickFix is a social engineering technique in which a web page persuades a user to copy a command and run it themselves, usually through the Windows Run dialog or a terminal, so the attacker never has to deliver a file.

Why today. Huntress's recap of ClickFix lures, fake verification pages and payloads is today's top story. Knowing where the technique leaves traces is what lets you hunt for it in Defender XDR and Sentinel. See story 1.

How the lure works

A ClickFix page imitates something users trust: a CAPTCHA or human verification check, a browser or document error, or a meeting app that claims a missing component. When the user clicks the button, script on the page silently places a command on the clipboard. The page then tells the user to press a key combination such as Windows+R, paste with Ctrl+V and press Enter, describing it as a verification or repair step.

Because the user runs the command, the attack avoids many controls that inspect downloads and attachments. No file is saved from the browser and there is no macro or exploit, and the first process runs in the user's own context. Variants use the Windows+X terminal, the File Explorer address bar, or the macOS Terminal, so blocking one input path does not end the technique. MITRE ATT&CK tracks this behaviour under User Execution as malicious copy and paste.

What the pasted command usually does

The pasted text is typically a short one-liner that calls a built-in Windows binary to fetch and run a second stage. Common choices are powershell.exe with a download-and-execute pattern, mshta.exe pointed at a remote URL, cmd.exe chaining curl or bitsadmin, msiexec.exe installing a remote package, and rundll32.exe. Attackers often pad the command with spaces or a fake comment, such as a line claiming to be a verification ID, so that the visible part of the Run box looks harmless.

Reported payloads range from infostealers and loaders to remote access trojans and legitimate remote management tools. That range is why Huntress describes varied payloads. Detection should focus on the shared delivery step rather than on any one malware family.

What it looks like in telemetry

A command typed or pasted into the Run dialog is launched by explorer.exe. In Defender XDR, DeviceProcessEvents will show explorer.exe as the initiating process of powershell.exe, mshta.exe, cmd.exe or similar, with a command line that contains a URL, an encoded block, or download functions. Legitimate users rarely launch these binaries with network arguments directly from the shell.

Windows also records Run dialog entries per user under the RunMRU key in the user's registry hive. In Defender XDR, DeviceRegistryEvents can surface new RunMRU values that contain powershell, mshta, curl, http or long obfuscated strings. Look next for a browser process holding a network connection shortly before the launch, for PowerShell script block logging (event 4104) showing the decoded second stage, and for new outbound connections from the spawned process.

How to prevent it

Where users do not need the Run dialog, Group Policy can remove it, and AppLocker or Windows Defender Application Control can block mshta.exe and limit script hosts for standard users. Attack surface reduction rules, such as the one that blocks potentially obfuscated scripts, add another layer. Their effect on a given ClickFix chain depends on the binaries it uses, so test them against your own environment. PowerShell Constrained Language Mode limits what an interactive one-liner can do.

User awareness still matters because the technique depends on the user's cooperation. The message is simple: no legitimate website or CAPTCHA will ever ask you to paste anything into Run, a terminal or the address bar. Make it easy for users to report a page that does.

For defenders

  1. Hunt in DeviceProcessEvents for explorer.exe launching powershell.exe, mshta.exe, cmd.exe, msiexec.exe or rundll32.exe with URLs, encoded content or download functions on the command line, and turn the high-confidence hits into a custom detection.
  2. Query DeviceRegistryEvents for new RunMRU values containing script hosts, http, curl or unusually long strings, which can reveal ClickFix executions that other telemetry missed.
  3. Block mshta.exe for standard users with AppLocker or WDAC, and remove the Run dialog through Group Policy for user populations that do not need it.
  4. Enable PowerShell script block logging and forward event 4104 to Sentinel, so the decoded second stage is visible when a pasted one-liner runs.
  5. Add a specific warning to security awareness material that no CAPTCHA, browser fix or meeting app will ask users to paste commands into Run, a terminal or the File Explorer address bar.
