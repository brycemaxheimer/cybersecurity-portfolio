No. 02 · Priority 47

Cursor confirms breach used to push a malicious Claude Code extension through its marketplace

Cursor Cursor · 1 source · first reported 14 November 2026

What happened

According to BleepingComputer, Cursor has confirmed a security breach that let attackers distribute a malicious Claude Code extension through its extension marketplace. BleepingComputer reports the attackers got in using credentials stolen from AI infrastructure provider Fireworks AI. The report was published on 14 November 2026. The available reporting does not name the extension, describe its payload, give a distribution window, or list indicators.

Why it matters

Developer workstations running the Cursor IDE may have installed a trusted-looking extension that runs code with the developer's privileges. That puts source code, API keys, cloud tokens and Microsoft 365 or Entra sessions on those machines at risk. Exploitation is confirmed, but the scope is unclear, so inventory and hunting are the main defenses until Cursor publishes details.

What to do

  1. Inventory endpoints running the Cursor IDE and review the Claude Code-related extensions installed or updated on them, removing any that Cursor identifies as malicious once it names them.
  2. On developer machines that installed or updated Claude Code extensions in Cursor during the incident window, rotate the secrets present there: API keys, cloud credentials, Git tokens and session tokens.
  3. Hunt for Cursor spawning shells, script interpreters or unusual outbound network connections on developer endpoints.
  4. Restrict or allowlist IDE extensions on managed developer workstations, and watch for vendor guidance from Cursor and Fireworks AI.
  5. Review Entra ID sign-ins and token activity for users of affected machines for anomalous locations or new devices.

What happened

NVD published six CVEs between 14 and 15 November 2026 covering Edimax BR6478ACV2, Tenda AC18, TRENDnet TEW-657BRM and D-Link DIR-600L router firmware. The flaws include stack-based buffer overflows and out-of-bounds writes in web management CGI handlers, plus a Tenda firmware upgrade handler that does not properly verify data authenticity. All are remotely reachable, and the NVD descriptions say exploits are public for each one. TRENDnet says the TEW-657BRM has been end-of-life for more than 15 years and it cannot confirm the issues, and Edimax reportedly did not respond to the reporter.

Why it matters

These are consumer and SOHO devices, so they show up at branch offices, home offices of remote staff, and in shadow IT rather than as managed corporate edge gear. None are in CISA KEV and EPSS scores are low (0.3% to 1.8%), but public exploit code for remotely reachable web interfaces is the kind of thing botnet operators pick up, and some devices will never be patched. The sources disagree on PoC availability: NVD text says exploits are public for all six, while proof-of-concept tracking confirms it only for the two TRENDnet CVEs.

What to do

  1. Find and replace any TRENDnet TEW-657BRM and D-Link DIR-600L units on corporate or branch networks; no fixes are stated and TRENDnet says the TEW-657BRM is long end-of-life.
  2. Make sure the web management interface of any Edimax BR6478ACV2 or Tenda AC18 is not reachable from the internet, and disable remote administration.
  3. Block corporate-managed or VPN-connected sites from relying on unmanaged consumer routers, and move branch connectivity to supported, vendor-maintained gear.
  4. Watch vendor channels for Edimax and Tenda firmware updates and apply them when they are released.
  5. Treat traffic from any of these devices as untrusted, and review for unexpected outbound connections from router IPs if they sit in front of corporate assets.

Explainer

Background, not news

Malicious IDE extensions: the code editor as a privileged supply chain

Extensions for VS Code and its forks, such as Cursor, run with the developer's full user privileges, so a poisoned extension or a hijacked publisher account gives an attacker code execution on machines that hold source code, cloud credentials and signing keys.

Why today. Cursor confirmed that attackers used credentials stolen from Fireworks AI to push a malicious Claude Code extension through its marketplace. That is the textbook form of this risk: a trusted distribution channel delivering attacker code straight to developer workstations. See story 2.

How editor extensions run

In VS Code and editors forked from it, extensions are mostly JavaScript or TypeScript packages that load into an extension host process. That process runs as the logged-in user. There is no per-extension permission model like the one browsers use: an installed extension can read and write any file the user can, start child processes, and open network connections.

The Workspace Trust feature limits what some extensions do when you open an untrusted folder. It is not a sandbox, though, and it does not restrict an extension you have already installed and enabled. Extensions also update automatically by default. A malicious version published under a trusted name therefore reaches existing users without anyone clicking anything.

Forks such as Cursor cannot use Microsoft's Visual Studio Marketplace under its terms. Many forks instead use alternative registries such as Open VSX, or run their own. Publisher verification, malware scanning and takedown speed differ from one registry to the next, so do not assume the same vetting everywhere.

How attackers get malicious code in

There are three common routes. The first is typosquatting or impersonation: a new extension whose name, icon and description copy a popular one. The second is a publisher account or publishing token compromise, where a legitimate, widely installed extension receives a malicious update. The third is compromise of the marketplace or its supporting infrastructure itself, which is what Cursor has described.

The second and third routes are the most dangerous because they skip the user's own judgement entirely. The extension name and publisher look exactly as they always have, and auto-update delivers the payload.

What an attacker gains

Developer workstations are high-value targets. They typically hold SSH keys, Git credentials, cloud CLI tokens, package registry tokens, .env files with API keys, and access to source repositories and CI/CD pipelines. AI coding tools add model provider API keys to that list.

A malicious extension can steal these secrets, plant persistence, or quietly change code before it is committed. That last option can turn one compromised developer into a downstream supply chain incident affecting the organisation's own customers.

What it looks like in telemetry

On Windows, extensions are installed under the user profile, for example in the .vscode\extensions folder for VS Code and the .cursor\extensions folder for Cursor. In Defender XDR, look for new or changed folders there in DeviceFileEvents. Correlate those changes with what the editor process does next.

The strongest behavioral signal is the editor process family (Code.exe, Cursor.exe and similar) spawning shells or download utilities: powershell.exe, cmd.exe, curl.exe, certutil.exe or rundll32.exe. Developers do run terminals from their editors, so build a baseline first and then alert on unusual command lines, encoded PowerShell, or child processes making outbound connections. Also watch DeviceNetworkEvents for editor processes contacting rare domains or paste and file-sharing services, and DeviceFileEvents for editor processes reading credential stores such as .ssh, .aws, .azure or browser profile data.

Prevention

Treat extensions as software you allowlist, not something each user picks freely. Current VS Code supports an enterprise policy that restricts which extensions or publishers can be installed, and it can be deployed through Group Policy or device management. Check whether each fork your developers use honours equivalent controls, because support varies.

Cut down the secrets an extension could steal. Prefer short-lived cloud credentials, hardware-backed or passphrase-protected SSH keys, and secret managers over plaintext .env files. Scope repository and registry tokens tightly so that one stolen token has a small blast radius.

For defenders

  1. Inventory which editors and AI coding tools (VS Code, Cursor and other forks) are installed across endpoints, and which extensions are in each user's extensions folder.
  2. Hunt in DeviceProcessEvents for Code.exe, Cursor.exe and similar editor processes spawning PowerShell, cmd, curl, certutil or rundll32 with unusual command lines, after baselining normal developer activity.
  3. Enforce an extension allowlist by publisher or extension ID through policy where the editor supports it, and document the gaps for forks that do not.
  4. For Cursor users, follow the vendor's guidance on the affected extension. Then rotate any credentials reachable from affected machines: Git and registry tokens, cloud CLI credentials, SSH keys and AI provider API keys.
  5. Move developers toward short-lived, narrowly scoped credentials so that secrets stolen from a workstation expire quickly and grant little.
