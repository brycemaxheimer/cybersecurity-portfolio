Methodology

How each edition is made

What is automated, what a model writes, what code decides, and what a person checks before anything is published.

1. Collection (code)

Every morning a script reads free public sources: the CISA Known Exploited Vulnerabilities catalog, NVD (recent high and critical CVEs), FIRST EPSS scores, Microsoft and CISA advisories, security news feeds, new SigmaHQ rules, an index of public proof-of-concept repositories, and posts that mention CVEs on Bluesky, Mastodon (infosec.exchange), r/netsec and Hacker News. X/Twitter is not used.

2. Ranking (model labels, code scores)

Claude Haiku groups items about the same event into stories and labels each one: exploitation status, how widely the product is deployed, and which platform it hits. The priority score is then computed by code from those labels plus facts the collector already has: KEV status, EPSS, CVSS and how many outlets reported it. CVE IDs on the page always come from the collected items, never from the model.

3. Summaries (model)

For the top stories, Claude Opus (or Sonnet) writes what happened, why it matters, affected and fixed versions, and what to do, using only the collected items. It cannot browse, run tools or add links: every link on the page was gathered by the collector and checked against an allowlist. Summaries can still be wrong or incomplete. Each one shows how well its sources supported it.

4. Detections (model and code)

If SigmaHQ already has a rule for a CVE, that rule is used and converted automatically. Otherwise the model drafts a Sigma rule, which code assembles and checks with sigma check; rules that fail are dropped. Rules are converted with pySigma to Defender XDR KQL, Splunk SPL and Elastic, and every KQL query is parsed with Microsoft's Kusto.Language against the Defender XDR and Sentinel schemas. Hunting queries that contain an indicator not found in the sources are dropped. Everything AI-generated is labelled "AI-generated, untested". Test and tune before you deploy anything.

5. Early signals (code)

A CVE becomes an early signal when several independent accounts post about it within the window and it is not yet in KEV or the news feeds. Accounts that post about many CVEs a day are treated as feed bots and posts naming many CVEs as digests; neither counts. No model is involved.

6. Review and publishing (a person)

Each edition is proposed as a pull request. Nothing is published until a person reviews and merges it. The site publishes summaries and links only, never copies of articles. Proof-of-concept repositories are listed as links, unvetted, with a warning.
